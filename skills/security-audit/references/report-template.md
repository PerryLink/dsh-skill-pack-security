# 审计报告模板（security-audit/references/report-template.md）

报告骨架：每个标题都是必填节，模板中的 `<...>` 为占位符。语言与主文件一致（中文为主，技术名词保留英文）。

## 模板

```markdown
# 安全审计报告：<仓库名>

- 审计对象：<仓库绝对路径>
- 基线提交：<40 位提交哈希>（<ISO 日期>）
- 审计时间：<开始>–<结束>
- 工具与版本：<gitleaks x.y.z / trivy x.y.z / pnpm x.y.z，不可用的注明"未执行">
- 审计人：<模型/工具名，注明"本报告由模型按 dsh-skill-pack-security/security-audit 流程生成，需人工复核">

## 1. 范围

纳入：<逐条路径/类别>
排除：<逐条排除项与理由>
假设：<子模块、上游镜像、CI 环境变量的处理方式>

## 2. 结论摘要

<一段话：发现 N 项（严重 X / 高 Y / 中 Z / 低 W），观察 M 项。最高风险是什么，建议的第一步行动是什么。>

## 3. 发现（每行含三要素与复核命令）

| 级别 | 发现 | 位置 | 可利用性 | 影响 | 已暴露 | 复核命令 | 处置建议 |
|---|---|---|---|---|---|---|---|

## 4. 观察（无法复核或未达"发现"标准）

<同表结构，级别一列写"观察"及原因。>

## 5. 验证命令附录

<阶段 4 中每条复核命令的原文与输出摘要，供审阅者重放。>

## 6. 方法限制

- 未执行的检查（缺工具/超出范围）：<逐条列出>
- grep 类降级路径覆盖不到的历史内容：<如适用>
- 模型判定、非工具判定：<逐条标注"需人工确认">
```

## 自检清单（交付前逐条过）

1. 每条"发现"都能用附录命令复核：`grep -n '<复核命令>' 报告.md` 预期命中每行。
2. 无密钥明文：`grep -nE '(ghp_[A-Za-z0-9]|AKIA[0-9A-Z]{16}|sk-[A-Za-z0-9]|-----BEGIN)' 报告.md` 预期无输出。
3. 每条发现的"可利用性/影响/已暴露"三要素非空：`grep -c '| 高 |' 报告.md` 等计数与发现数一致。
4. 基线提交哈希为 40 位 hex：`grep -oE '[0-9a-f]{40}' 报告.md` 至少命中一次。
5. 方法限制节非空：`grep -A5 '## 6' 报告.md` 有实质内容。
