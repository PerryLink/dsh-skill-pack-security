# 风险分级细则（security-audit/references/risk-classification.md）

主文件阶段 3 的完整定义。定级只用三要素：**可利用性 × 影响 × 是否已暴露**，三者都写进报告行，缺一不可。

## 四级定义

| 级别 | 定义 | 处置时限 | 报告措辞模板 |
|---|---|---|---|
| 严重（Critical） | 已暴露的真实凭据、可直接远程利用的漏洞、绕过所有防护的注入面 | 立即处理，审计结束前给出处置 | "已确认：<类型> 在 <位置> 暴露于 <范围>，具备 <影响>。" |
| 高（High） | 可本地/低权限利用，或影响面大但利用需要前提条件 | 本次迭代内处理 | "发现：<类型> 在 <位置>，利用前提为 <前提>。" |
| 中（Medium） | 纵深防御缺口、配置隐患、依赖中无可利用路径的已知漏洞 | 排期处理 | "观察：<类型> 建议在 <版本/计划> 中处理。" |
| 低（Low） | 信息暴露、样式/卫生问题、历史遗留 | 记录在案 | "记录：<类型> 不构成当前风险。" |

## CVSS 粗映射（仅作参考，不替代三要素）

- Critical 9.0–10.0 → 严重
- High 7.0–8.9 → 高
- Medium 4.0–6.9 → 中
- Low 0.1–3.9 → 低

判据：CVSS 只是上游评分；本仓库是否受影响必须由三要素重估（例如只在 devDependencies 中且不参与构建的漏洞包，即便 CVSS 为 critical，也可降为中并写明理由）。

## 复核命令

| 发现类型 | 复核命令 | 通过判据 |
|---|---|---|
| 密钥 | `git grep -n '<前 6 字符>' <提交哈希> -- '<路径>'` | 输出命中行且内容为凭据格式 |
| 依赖漏洞 | 在 `pnpm audit --json` 输出中检索 advisory id | 该 id 存在且 `severity` 匹配报告 |
| 新增依赖 | `git log --oneline --follow -- <锁文件>` | 引入提交存在且与该依赖版本对应 |
| 注入面 | 原文出处 grep（见 prompt-injection-review） | 原文存在且上下文与引用一致 |

## 升级/降级规则

- 无法复核的定级 → 一律降为"观察"。
- 复核失败（命令无输出、内容不符）→ 降为"观察"或删除；不删除但保留原级别的，必须在报告写原因。
- 同一根因的多条发现合并为一条，在行内列出全部位置。
